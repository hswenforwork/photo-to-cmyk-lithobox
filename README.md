# 照片轉線稿＋CMYK分層＋3D浮雕工具

離線可用的純前端網頁工具：上傳一張生活照片，輸出3D列印彩色燈箱需要的全部檔案——原始裁切照片、灰階高度圖（3D列印浮雕用）、外層裝飾層（熄燈裝飾層用，提供「日式似顏繪風格」與「素描風」兩種風格可切換），以及3D列印用的STL模型。內建AI主體偵測（本機執行，人物／動物輪廓辨識）與AI日式動畫風格轉換，照片全程不會上傳到任何伺服器。

**輸出尺寸**：A5、6×4吋、7×5吋、5×3.5吋（L判標準尺寸）或**自訂尺寸**（直接輸入寬／高，單位mm，範圍20～400mm）可選，直向／橫向切換，尺寸自動四捨五入為整數mm；裁切構圖支援水平鏡像翻轉。

**外層裝飾層有兩種風格可選：**
- **日式似顏繪風格**：以本機執行的AI圖像風格轉換模型（CartoonGAN）將照片轉換為帶有簡單色彩、俐落墨線的日式動畫風全彩插畫，可選宮崎駿吉卜力風／細田守風／今敏風／新海誠風四種畫風，並提供「似顏繪細緻度」「色調」「色溫」「飽和度」四個滑桿微調——細緻度負值方向讓畫面更簡化、更接近色塊平塗，正值方向則用unsharp mask銳化加強線條與紋理細節；色調透過色相旋轉整體調整色彩；色溫負值偏冷藍、正值偏暖橘；飽和度負值趨近灰階、正值加強彩度。四者皆為輕量後製（canvas運算，非AI），拖曳時直接套用在已快取的AI結果上即時更新，不需要重新跑AI。
- **素描風**：模擬鉛筆素描的濃淡漸層與交叉排線筆觸，純程式化濾鏡效果（非AI模型）。

兩種風格皆只會套用在「主體遮罩」範圍內（忽略背景），且即時合成預覽（點燈／熄燈）會自動跟著目前選擇的風格切換。由於「日式似顏繪風格」需要跑AI模型、運算成本較高，即時預覽**不會**隨裁切/縮放/尺寸調整自動更新，需按「產生／更新預覽」按鈕手動觸發，避免拖慢瀏覽器；其餘圖層仍為即時預覽。「點燈」模式的背光色溫改為3000K～6500K連續滑桿，依實際色溫換算成對應色光（Kelvin轉RGB近似公式）疊加，取代先前的暖光/白光二選一下拉選單與獨立的整體穿透衰減／邊緣暗角效果。

**左右鏡射翻轉開關**：「即時預覽 — 各圖層」的原始照片、灰階高度圖、外層裝飾層三張卡片下方，各自提供一個獨立的左右鏡射翻轉開關，預設皆關閉（維持與原始圖檔相同的方向），三者互不影響，可任意單獨或組合開啟。這是純顯示/輸出層級的最終翻轉（不影響AI輸入內容），跟③裁切構圖區的「水平鏡像翻轉照片」不同——後者是在裁切/構圖前先翻轉來源照片本身，會連帶影響構圖與AI風格轉換的輸入且三張圖層同步；這裡的三個開關則是在所有運算完成後才各自套用，切換時不需要重新跑AI。**即時合成預覽（熄燈／點燈）固定以原始方向顯示，不受這三個開關影響**。下載列印圖層PDF的每張圖層，會依其對應開關**當下**的狀態輸出鏡射或未鏡射，與該圖層的即時預覽保持一致。

**下載列印圖層**：列印用圖層（原始照片、灰階高度圖、外層裝飾層，共三張，**不含C/M/Y分色版**）會自動排版到儘量少張的A4紙上——同一張A4能放下幾張圖層就放幾張，並統一預留5mm列印邊界；圖面本身不含任何文字標籤，只保留裁切用的虛線框。每張圖層都會在步驟①輸出尺寸的邊界外再外擴5mm留白出血邊（實際物理尺寸＝輸出尺寸+10mm），四角十字線／打孔圓點對位記號（固定直徑3mm）畫在這個外擴後的新邊界，換算下來恰好落在原始輸出尺寸的邊界上。所有頁面會合併輸出成**單一PDF檔案**（不再是個別PNG檔），每頁一張圖片、色彩空間為**DeviceCMYK**（適合印刷用途，避免RGB送印時被印刷軟體/驅動程式自行做不可預期的色彩轉換），可直接家用印表機列印。**三張圖層是否左右鏡射翻轉，依「即時預覽 — 各圖層」下方的鏡射翻轉開關目前狀態統一決定**（詳見下方說明）。C/M/Y分色不再提供使用者可調濃度滑桿、也不再有個別預覽卡片，內部固定以100%濃度計算，僅供「即時合成預覽」點燈模式的全彩混色使用。

**CMYK色彩轉換說明**：PDF內的CMYK數值本身是標準公式換算（K=1-max(R,G,B)，其餘channel依K再正規化），純粹的數值轉換，不是經過ICC色彩管理的轉換。PDF另外會內嵌「Japan Color 2011 Coated」印刷色域描述檔（`assets/JapanColor2011Coated.icc`，取自ICC色彩描述檔登錄資料庫 https://registry.color.org/profile-registry/JapanColor2011Coated ，授權允許使用/嵌入PDF/交換/分享，檔案內容未經修改）作為PDF的OutputIntent（`/S /GTS_PDFX`），這是業界慣用的「印刷就緒PDF」宣告方式，讓支援的印刷軟體/RIP知道這份CMYK數值對應的印刷條件依據；描述檔約1.9MB，首次下載時瀏覽器會另外抓取一次並快取，下載失敗時仍會正常產生PDF，只是不含這項宣告。一般家用或桌上印表機直接使用目前的CMYK數值即可正常列印。

**下載/匯出絕不會重新執行日式似顏繪風格AI**：一律直接沿用④「產生／更新預覽」已經算好的結果放大使用。任何會改變AI輸入內容的操作（上傳新照片、裁切位置/縮放、輸出尺寸、直向/橫向、水平鏡像、主體遮罩開關/清除/手動繪製/AI偵測、切換畫風）都會讓這份快取立即視為過期；「下載列印頁面 PDF」按鈕只要目前選到的模式是日式似顏繪風格且快取不存在或已過期，就會直接被擋下並顯示清楚的提示訊息，而不會靜默地在下載當下重新跑一次AI或送出跟預覽不一致的內容。

**輸出檔名**：下載的PDF與STL檔名固定為「YY-MM-DD HH-MM_原始照片檔名」（時間為下載當下時間，日期時間以`-`分隔，因為`/`無法用於檔名），例如上傳`sunset.jpg`後於2026年9月18日14:32下載，檔名為`26-09-18 14-32_sunset.pdf`。

**介面操作體驗**：每個步驟操作框標題列可點擊收合/展開，方便微調參數時直接對照右側預覽，不必為了看到預覽而往下捲動整個頁面；各步驟操作框文字只保留操作/步驟說明，套件說明、授權與致謝等資訊統一收錄在頁面最底部。

## 部署到 GitHub Pages

1. 在 GitHub 建立一個新的 repository（公開或私有皆可，公開才能用免費的 GitHub Pages）。
2. 把這個資料夾裡的所有檔案（`index.html` 與整個 `assets/` 資料夾）上傳到 repo 的根目錄。
   - 可以直接在 GitHub 網頁介面用「Add file → Upload files」把檔案拖進去，或用 `git push` 上傳。
   - `assets/` 資料夾裡的檔案（AI模型、onnxruntime-web、fflate）**務必整個一起上傳**，工具需要它們才能運作。
3. 到 repo 的 **Settings → Pages**，Source 選擇 `Deploy from a branch`，Branch 選擇你放檔案的分支（通常是 `main`）與資料夾 `/ (root)`，儲存。
4. 等待一兩分鐘，GitHub 會給一個網址（通常是 `https://<你的帳號>.github.io/<repo名稱>/`），開啟即可使用。

## 隱私與離線說明

- 照片只在使用者自己的瀏覽器裡處理（Canvas運算＋本機AI推論），不會上傳到任何伺服器。
- 唯一的網路連線是「首次使用某項功能時，瀏覽器向同一個網站下載 assets/ 裡對應的程式庫/模型/描述檔」（AI主體偵測約19MB、日式似顏繪風格每種畫風約13MB、下載列印PDF用的CMYK印刷色域描述檔約1.9MB，皆只會下載一次，之後瀏覽器會快取），這與照片內容完全無關。
- 頁面已設定 Content-Security-Policy 限制對外連線僅能是同網站內的資源（`connect-src 'self'`），技術性防止任何第三方連線；`script-src` 因TensorFlow.js執行時需要而包含 `'unsafe-eval'`，僅影響本頁自身程式碼的執行彈性，不影響前述的連線限制。

## 已知限制 / 之後可能的加強方向

- AI主體偵測目前使用通用的顯著物體偵測模型（U²-Netp，非針對特定類別訓練），對大部分人物、寵物（貓、狗等）效果良好，但無法保證100%準確，遇到複雜背景或多個主體時建議搭配手動筆刷微調。偵測完成後會自動做兩項純運算的後處理：(1) 以連通區塊分析去除面積過小（低於總面積0.5%）的雜訊區塊；(2) 對遮罩邊緣做輕度羽化，讓邊界過渡更平滑。**技術限制**：目前vendor的 `u2netp.onnx` 模型輸入尺寸是寫死的320×320（並非動態尺寸的全卷積網路），無法單純調高常數來提升輸入解析度（實測直接餵入512×512會被onnxruntime拒絕並丟出尺寸不符錯誤）；若要真的提高偵測解析度，需要更換一個支援更大或動態輸入尺寸的模型檔案，這會增加下載體積，屬於較大的改動，目前尚未實作。
- 日式似顏繪風格為圖像風格轉換（CartoonGAN），效果會依照片內容、光線與構圖而異，並非傳統五官誇張變形的手繪似顏繪；運算成本較高，預設會依序嘗試WASM→WebGL（含偵測軟體模擬WebGL自動跳過）→CPU運算。優先使用WASM而非WebGL，是因為WASM不需要編譯瀏覽器/顯示卡專屬的vertex/fragment shader，對不同公用電腦、顯示卡驅動與瀏覽器組合較穩定，可避免「Failed to link vertex and fragment shaders」之類shader編譯失敗的問題。即時預覽需手動按「產生／更新預覽」按鈕觸發，不會隨裁切/縮放即時自動更新。運算過程中若遇到貼圖尺寸超限、WebGL錯誤、shader編譯/連結失敗或逾時等可恢復的錯誤，會自動依序改用其餘尚未嘗試過的運算方式（wasm/webgl/cpu）重試，全部失敗才顯示最終錯誤；所有AI模型下載與運算步驟也都加上逾時保護（模型下載60秒、單次風格轉換120秒、backend初始化30秒），逾時會清楚顯示錯誤訊息，而不會無限期卡住、毫無提示。
- AI實際運算解析度固定為單一工作尺寸（**512px**，預覽與下載/匯出共用同一份），**下載/匯出絕不會重新執行AI**：一律直接沿用「產生／更新預覽」已經算好的結果等比放大，並記錄產生當下對應的照片/裁切/尺寸/方向/鏡像/遮罩/畫風版本編號與已選畫風；上述任何一項之後若再被改動，這份快取就會立即視為過期，下載時會被擋下並提示需要重新產生預覽，而不會送出跟畫面不一致的內容，也不會為了輸出而用不同尺寸重新跑一次AI模型（這曾在部分顯示卡/驅動組合上因為同一頁面對同一模型重複觸發不同尺寸的WebGL shader編譯而導致連結失敗錯誤）。**技術限制**：實測發現把工作解析度提高到720px以上時，在沒有真實GPU加速、退回WASM backend運算的情況下，連續多次按「產生／更新預覽」（使用者反覆調整裁切/畫風時的正常操作）會讓每次運算逐漸變慢，最終導致分頁失去回應——原因是WASM的線性記憶體只會成長不會釋放，大尺寸推論反覆執行會持續累積記憶體壓力；512px則實測連續5次都能穩定維持在同樣的運算時間，不會有這個問題。因此目前選擇512px作為兼顧畫質與穩定度的預設值，尚未支援720p以上的工作解析度；未來若要挑戰更高解析度，需要先解決WASM記憶體只增不減的問題（例如偵測到記憶體壓力後定期重建tf引擎/backend），而不能只單純調高解析度常數。
- 素描風線稿目前是第一階段的純程式化濾鏡（負片＋模糊＋加亮混合明暗骨架＋固定角度交叉排線），效果較保守、規律，尚非手繪等級的逼真筆觸。
- 3D模型匯出目前只提供 STL（相容性最廣，Cura／PrusaSlicer／Bambu Studio皆可直接匯入）；3MF格式較複雜，暫未提供。
- **STL底板外擴與對位孔**：3D列印的底板會比照列印圖層的出血邊設計，在步驟①輸出尺寸外緣外擴5mm，並在四角開直徑3mm的貫穿孔（供組裝時穿螺絲/銷釘，跟其他圖層的對位孔位置概念一致，但3D孔洞的中心點刻意選在出血邊寬度的中點，而非跟紙本記號一樣直接對齊出血邊界，確保孔洞完全落在平坦區域、不會跟中央浮雕實體重疊，才能形成真正貫穿的乾淨孔洞）。技術實作上，浮雕實體與外擴底板邊框是各自獨立、互相密合貼齊的STL實體（邊框用細格點陣近似圓孔形狀），這是STL多實體組合檔案常見且被slicer軟體良好支援的做法；已用Python的trimesh/manifold3d驗證：拆解出的9個獨立幾何區塊皆個別為watertight（可正確計算體積、無破面），且布林聯集（union）運算能成功合併為單一watertight實體，體積與孔洞位置符合預期，可放心匯入slicer切片。
- **STL「僅輸出底板」模式**：勾選⑥區塊的選項後，輸出改為整片固定底板厚度的平板（同樣外擴5mm並於四角開對位孔），不含灰階浮雕，方便先列印/測試底板尺寸與對位孔是否吻合，再列印含浮雕的完整版本。
- 建議實際列印/3D列印前，先用「即時合成預覽」抓大方向，實際效果仍需以實體測試微調各項參數（尤其灰階厚度換算）。
